# Go 1.27 与 Paimon JSON 后端契约

## 模块与兼容边界

主模块使用 Go 1.27.0，Sonic 公共 import path 由发布版 Paimon v0.1.0 提供：

```go
go 1.27.0

require github.com/bytedance/sonic v1.15.2

replace github.com/bytedance/sonic => github.com/hugefiver/paimon-go v0.1.0
```

生产代码、测试及上游依赖继续导入 `github.com/bytedance/sonic`，不修改上游源码，
也不以本契约授权升级无关依赖。不使用本地 replacement、未发布分支或 pseudo-version。
实际编译依赖不得包含 `github.com/bytedance/sonic/loader` package；模块图中的 loader
module 记录不构成失败，也不需要用 `exclude` 删除。模块文件须通过 `go mod tidy -diff`。

兼容性以真实 Eino 载荷的解码结果或规范化 JSON 为准，不要求 malformed JSON 错误文本、
map key 字节顺序或 native/JIT 行为一致。不实现 Sonic native/JIT、assembly，
不迁移到 `encoding/json/v2`，也不以本契约扩大平台功能。

## 功能与性能要求

`agent/json_backend_compat_test.go` 检查 replacement 构建身份和代表性 Eino JSON 语义。
功能边界包括 `Marshal` / `Unmarshal`、string API、`Valid`、`GetFromString` 与 AST，
以及 message/tool-call/function arguments、JSON Schema 嵌套 map/slice、自定义
`json.Marshaler`、Unicode、转义、整数、浮点、`json.Number`、null 和 malformed/trailing JSON。
上层 agent、MCP 和 streaming 测试仍是集成证据，不复制后端自身的完整测试套件。

性能要求独立于 race 检查。在同一进程、同一代表性 Eino payload 上，用
`testing.Benchmark` 分别比较 marshal 和 unmarshal，每项必须满足：

```text
paimon ns/op <= encoding/json ns/op * 2.5
```

不得提高阈值、合并两项平均值或靠跳过测试掩盖失败。诊断 benchmark 还覆盖 nested
`GetFromString` 与 `Valid`，以 `-benchmem` 报告延迟和分配；分配不是硬门禁，
不设置机器相关的绝对纳秒阈值。非 race 性能门禁必须在 CI 中单独执行，不能被 race
构建条件隐藏。

**当前覆盖缺口：** 仓库有功能兼容测试，但未提供对应的非 race 性能测试、
`make test-json-performance` 目标或独立 CI 步骤。2.5 倍要求不能据此视为已验证。

## 构建与验证

GitHub Actions 使用 `1.27.x`，Docker 使用 `golang:1.27-alpine`，只跟随补丁版本，
不自动跨到 1.28。Travis、golangci-lint 和 Dev Container 使用 Go 1.27。
lint 验证须显式传 `--fix=false`，避免仓库配置的自动修复修改工作树。

验证覆盖 replacement 身份、功能与非 race 性能、普通与 race suite、native build、
格式检查、lint、tidy 和 Docker 镜像构建。Docker 不可用时须明确未验证，不能记为通过。
Linux `amd64`、`arm64`、`386`、`arm/v7` 的 `CGO_ENABLED=0` 构建范围不能缩小；
可构建不代表每个平台都具有相同运行时能力。

## 回滚

回滚需移除 Paimon replacement 及其专用直接依赖、测试和性能门禁，协调恢复全部活跃
Go 版本设置，并重新整理和验证模块依赖。不能只改一个版本设置后混用不同 JSON 后端。
这里没有 Redis、数据格式或其他持久化迁移。
