# Agent 群记忆

群记忆是同一聊天内共享的参考资料，按「分类 > 目录」组织。每轮模型先看到分类、目录标题和单行用途说明。需要回答时，模型只打开相关目录，取得条目 ID，再读取选中条目的正文。目录说明写清这里适合放什么，建议不超过 20 字，不硬性限长。目录沿用首条记忆创建时的说明，直到删空。

## 在聊天里使用

按已配置的 Agent 触发方式发消息，例如 `/chat 请帮我记住周五在图书馆开会`，或在已启用回复触发时直接回复 bot。独立的 `/memory` 命令（`add`、`list`、`forget`）已移除。以下写法是发给 Agent 的消息。

| 要做什么 | 发给 Agent 的消息 |
| --- | --- |
| 召回 | `例会在什么时候？`，也可以指定分类或目录来缩小范围。 |
| 新增并自动归类 | `请帮我记住周五在图书馆开会`，或 `记住：周五在图书馆开会`。 |
| 新增到指定目录 | `新增群记忆 [活动>例会]（例会时间地点）：周五三点开会`。 |
| 保存一条同群消息 | 回复该消息，发送 `把这条记到群记忆 [活动>例会]`。可省略路径让 Agent 归类；在 Telegram 中选中引用片段时，只保存该片段。 |
| 整理本次对话 | `总结本次会话并记入群记忆 [活动>例会]`。Agent 根据当前可见的对话写入一条摘要；仅要求总结不会保存。 |
| 替换 | `替换群记忆 [活动>例会] mem_123456789abc：周五四点开会`。 |
| 删除 | `删除群记忆 mem_123456789abc`。 |

新增成功会返回条目 ID。替换和删除请填真实的完整 ID，可省略目录路径；不确定 ID 时，先让 Agent 查找并确认。替换保留原 ID、目录、创建者和创建时间，正文用冒号后的文字整体替换。删掉目录最后一条记忆后，该目录从索引中消失。

普通聊天不会自动写入。新增、替换的正文取自本条请求或明确选中的同群回复；只有明确要求「总结本次会话并记入群记忆」时才会写入模型生成的摘要。若想先审核摘要，可以只请 Agent 起草，核对后再回复草稿「把这条记到群记忆」。

## 谁能看到和修改

同群成员只要能使用前台主 Agent，就能询问共享记忆，包括别人添加的条目。写入权限单独判断：默认 `explicit_or_admin` 仅允许管理员增删改；`explicit_quota` 也允许普通成员新增，以及替换、删除自己添加的条目。管理员能管理所有条目，不受个人条数限制。群内管理员按「可限制成员」权限判定；私聊独立于任何群聊，按管理员权限处理。不要保存不宜向同群成员公开的内容。

新增受个人配额（如适用）和聊天容量限制；替换不占用新名额，仍受容量限制。Redis 在同一事务内检查适用的限制并更新条目与目录索引。

群记忆召回独立于会话历史。删除条目后不能再从记忆目录召回它，之前发到聊天里的消息和已生成的回答不会因此被删除。会话归档和压缩的边界见[完整模型会话上下文](agent_session_context.md#如何选择历史)。

## 部署与配置

以下键均位于 `agent_v3.memory`。群记忆使用现有 Redis，无需额外挂载、环境变量、`TZ` 设置或后台任务。

| 键名 | 缺省值 | 行为 |
| --- | --- | --- |
| `enable` | `false` | 仓库示例显式设为 `true`；显式关闭后停用目录、召回和管理，不删除数据。 |
| `scope` | `group` | 只支持按聊天隔离，其他值回退为 `group` 并记录 warning。 |
| `allow_global` | `false` | 不提供全局记忆；设为 `true` 会回退为 `false` 并记录 warning。 |
| `write_policy` | `explicit_or_admin` | 仅管理员可写；设为 `explicit_quota` 允许普通成员按配额管理自己的条目。其他值回退为默认值并记录 warning。 |
| `max_entries_per_user` | `20` | 仅 `explicit_quota` 下限制普通成员每人可持有的条数；小于等于零使用默认值。 |
| `snapshot_max_tokens` | `2000` | 聊天内记忆正文的容量预算，按每单位约 4 个 Unicode 字符折算，默认约 8000 字符；小于等于零使用默认值。 |

Redis Hash 键为 `<prefix>:agentv3:<bot>:tg:<chatID>:group_catalog`，按机器人、平台和聊天隔离。键无 TTL，不受 `agent_v3.context_cache.redis_ttl` 影响。现有 [Redis 配置](../redis.conf) 使用 `allkeys-lfu`，内存不足时仍可能淘汰无 TTL 的键；需要保留的记忆应纳入 Redis 持久化和备份。

### 升级与回滚

升级后从新的空目录开始使用。新版只使用新命名空间，不探测、读取、迁移或清理旧记忆。无需手工调整 Redis 键；若要继续使用某条已知旧记忆，请通过 Agent 重新新增。

回滚时切回旧 bot 版本和对应的配置。旧版重新使用原命名空间，只能看见仍保留的旧记忆；新版新增、替换和删除不反映到旧命名空间。`group_catalog` 可留在 Redis，旧版会忽略它；再次升级仍可使用其中保留的数据。
